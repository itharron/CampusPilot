# CampusPilot 演示视频脚本（5–8 分钟）

- 目标时长：**7 分 37 秒**（允许 7:15–7:45，即 7:30 ± 15 秒）
- 录制对象：线上演示环境 <http://47.96.20.128:8787>（若线上不是最新语料，见 1.4，可改用本机 `npm start`，界面一致）
- 语言：普通话；口播稿可逐字照念，不必临场组织语言
- 结构：片头标题 → 首页与示例 → 知识库作答 → 推测与候选 → 转人工 → 拒答 → 登录 → 50 MB 超限 → 拖拽上传 → 确认入库 → 回对话验证 → AI 技术亮点 → 移动端亮暗切换 → 收尾
- 全文只有一套时间轴：15 段，按录制顺序排；除手机段单独用手机录制、后期插入外，录制顺序即成片顺序

> 录制前先完成「一、录制前准备」的全部事项，否则登录、上传与超限三段会没有可用数据。

## 一、录制前准备

### 1.1 画面与 OBS

| 项 | 要求 | 怎么确认 |
| --- | --- | --- |
| 显示器分辨率 | 1920×1080 或更高，系统缩放 100% | 桌面右键 → 显示设置，确认「缩放 100%」 |
| 浏览器 | Chrome，窗口最大化，缩放 100%（Ctrl+0） | 地址栏右侧百分比确认 |
| OBS 画布 | 设置 → 视频 → 基础（画布）分辨率 **1920×1080** | 不要用「窗口捕获 + 裁切」，否则宽度会不足 1920 |
| OBS 输出 | 输出（缩放）分辨率 **1920×1080**，30 fps | 设置 → 视频 |
| 录制源 | **显示器捕获**（不是窗口捕获） | 拖拽文件时资源管理器要入镜，窗口捕获拍不到 |
| 编码 | x264，CBR，**10000 Kbps**（8–12 Mbps 区间），关键帧 2 秒 | 设置 → 输出 → 录像 |
| 封装 | MP4 | 同上 |
| 音频 | 48 kHz，AAC 192 kbps | 设置 → 音频 |
| 试录 | 先录 15 秒，用播放器看属性 | 必须 1920×1080、约 10 Mbps、有音轨 |

桌面布局：Chrome 最大化放在屏幕右侧占约 3/4 宽；资源管理器打开到存放 `library-room-booking.md` 与 `oversize.md` 的文件夹，放在左侧，两个文件都可见。关闭所有无关窗口、下载条与更新提示。

### 1.2 麦克风与界面清理

1. 用领夹麦或耳机麦，不要用笔记本内置麦。
2. OBS 麦克风滤镜加「噪声抑制（RNNoise）」与「增益」；正常说话峰值落在 **−12 至 −6 dBFS**，不要顶到 0。
3. 录 10 秒试音，回放确认无爆音、无电流声、无键盘声。
4. 书签栏隐藏：Chrome 按 **Ctrl+Shift+B**。
5. 关闭或退出 **Kbot** 悬浮条，确认右上角不再出现「Kbot >」。
6. 关闭系统通知（勿扰模式），退出微信、QQ、钉钉等会弹窗的应用；地址栏右侧只留必要图标。
7. 只开三个标签页：对话页、`/upload`、技术文档（`docs/tech-report.html`）。

### 1.3 浏览器状态与登录

1. 打开 DevTools → Application → Local Storage → 删除键 **`campuspilot-theme`**，刷新。
2. 确认首屏是**亮色**。若系统是暗色，先点右上角圆形按钮切到亮色，再刷新确认仍是亮色。
3. 确认对话页没有历史消息，输入框为空；页面底部「知识库 N 篇 / N 个片段」与 1.4 一致。
4. 确认顶栏右侧显示的是 **「登录」**，不是「退出」。
5. 直接访问 `/upload`，必须看到 **「知识库入库需要登录」** 卡片；若已是「已登录为 demo」，点顶栏「退出」后刷新重来。

### 1.4 模型、额度与线上版本

1. 顶栏必须显示 **「真实模型 · <模型名>」**；显示「Mock 演示模式」或「连接中…」都不开录。
2. 打开 `/api/health`，确认 `ok=true`、`mode=live`、`retriever=bm25`。
3. **预热**：先问一个不录进视频的问题（例如「奖学金什么时候评」），确认回答正常、无任何降级提示。
4. 确认底部「今日剩余」次数足够本片使用（全片约 8 次提问，留 20 次以上余量）。
5. 确认 `corpus.docs=11`、`corpus.chunks=33`。若仍是 `10 / 30`，说明线上还没部署含「成绩单打印」的最新 `main`：先部署，或改用本机 `npm start` 录制。
6. 若预热就出现「模型服务暂时不可用」，换 Key 或改用本机 `npm start`，不要带病开录。

### 1.5 待用文件

| 文件 | 要求 | 用在哪一段 |
| --- | --- | --- |
| `library-room-booking.md` | **纯 ASCII 文件名**，UTF-8，约 1 KB，内容见 1.6 | S10、S11、S12 |
| `oversize.md` | 恰好 53477376 字节（51.0 MB）：`fsutil file createnew D:\demo\oversize.md 53477376` | S9 |
| 标题页 | OBS「场景 2」：深蓝色源铺满画布 + 三行文本：`CampusPilot` / `校园「一句话办事」服务台` / `想过周六 · 三江学院` | S1 |

> 为什么文件名必须是 ASCII：服务端拿到的 `originalname` 对中文名会显示成乱码，「已切分为…」和「入库成功」的出处都会带乱码。中文只写在表单的「文档名」里。

### 1.6 待上传示例文档

把下面这份**纯文本**存为 `library-room-booking.md`。服务端会把首行短标题和「第X条」短行自动升级为切块标题，所以不要自己写 `##`，否则会变成 `## ##`：

```text
图书馆研讨间预约
第一章 空间与预约，图书馆三层研讨间面向在校学生开放，用于小组讨论、课程项目与竞赛备赛，不得用于商业活动或长期占位。
第二条 预约方式
通过图书馆主页「空间预约」入口选择研讨间与时段，刷卡入场。每人每天最多预约两个时段，每个时段两小时。
第三条 所需材料
预约时填写学号与联系电话；入场时携带校园卡。超过预约开始时间十五分钟未刷卡，系统自动释放该时段。
第四条 注意事项
研讨间内禁止饮食，离开时请关闭投影与空调。连续两次预约未到场，七天内不能再预约。
```

这份内容会得到：标题自动带出「图书馆研讨间预约」、章节自动带出「第一章 空间与预约」、切成 4 个片段；只有「文档名」需要手改成中文。

### 1.7 输入法与知识库现状

- 输入法切到**中文**，候选栏不要有未上屏的拼音；手输前先按一次 `Esc`，确认输入框里没有下划线拼音。
- 每输完一个词按 `Enter` 上屏，再检查输入框；确认无拼音残留后才按发送。
- 能在示例按钮里点到的问句，一律不手输。
- 确认「当前知识库」里没有同名的「图书馆研讨间预约」；若有，把标题改成「图书馆研讨间预约（演示）」并在口播里同步。
- 关闭 VPN / 代理，避免真实模型请求超时。

## 三、分段脚本（按录制顺序）

> 每段结构：画面 → 精确动作 → 逐字口播 → 录完自检。标【必须一次成功】的段落，失败就整段重录，不能靠后期补救。

### S1 片头标题（00:00–00:08，8 秒）

**画面**：全屏 16:9 标题页，只有项目名、定位、团队，无鼠标、无桌面图标。

**动作**：
1. 切到 OBS「场景 2」，开始录制，停 2 秒再开口。
2. 念完保持画面 2 秒，停止录制；切回浏览器场景。

**口播**（22 字）：
> CampusPilot，校园「一句话办事」服务台。

**自检**：画面里必须有 `CampusPilot` 与 `校园「一句话办事」服务台`，且没有浏览器、任务栏、鼠标指针。

### S2 首页首屏：示例必须是收起态（00:08–00:22，14 秒）

**画面**：线上首页。必须出现标语「不用查手册，把要办的事说一句话」、三步引导、3 条主示例、「更多示例」按钮、底部知识库规模。

**动作**：
1. Chrome 打开 <http://47.96.20.128:8787>，等页面完全加载，鼠标移到画面右侧空白处停住。

3. 确认示例区只有「宿舍空调坏了」「我要开在读证明」「教室怎么借用」三条，**没有分组标题**。
4. 鼠标停住，不要点任何按钮。

**口播**（37 字）：
> 线上打开就能用，不用安装。首页是一句话提问，下面是三步引导和三条高频示例。

**自检**：
- 画面里必须同时出现「不用查手册，把要办的事说一句话」和「更多示例」。

### S4 知识库作答：教室怎么借用（00:36–01:26，50 秒）【必须一次成功】

**画面**：完整一轮问答：路径标签、意图标签、`bm25 检索` 标签、逐字流式回答、部门与步骤、依据来源卡片、展开原文与高亮。

**动作**：
1. 点主示例「教室怎么借用」。
2. 回答开始后不要滚动，等路径卡与第一段文字出现。
3. 回答结束后，鼠标指向路径标签「路径：知识库作答」，停 0.5 秒。
4. 滚到「依据来源 · 点击可查看原文」，点第一条的「展开原文」。
5. 缓慢向下滚两行，让 `mark` 高亮词入镜，停 1 秒；点「收起」。
6. 鼠标移开。

**口播**（约 136 字）：
> 先点「教室怎么借用」。回答上方先给出路径：知识库作答，同时标出意图和 bm25 检索命中的片段数。回答逐字出现，写明归属部门、办理入口、步骤和材料。下面「依据来源 · 点击可查看原文」，点「展开原文」，能看到文档名、章节和手册原文，和提问重合的词会高亮；点「收起」回到列表。

**自检**：
- 必须出现「路径：知识库作答」「意图：」「bm25 检索 · N 个片段」。
- 回答里必须出现归属部门与办理入口的具体文字，不是空模板。
- 必须出现「依据来源 · 点击可查看原文」，且点开后出现「收起」和至少一处高亮。
- **绝对不能**出现「模型服务暂时不可用，先按本地知识库给你一份指引：」或底部错误条「模型服务暂时不可用，以上内容来自本地知识库。」

**失败回滚**：
- 出现降级文案：停止录制，刷新页面，重问同一句；连续两次仍出现就换 Key 或改本机 mock，整段重录。降级画面一帧都不能留。
- 出现「命中缓存」标签：不影响正确性，但会让“真实模型”显得可疑；换一个等价问句（如「教室借用流程」）重录本段。
- 没有引用卡片：等 2 秒仍未出现就重录。

## 六、后期处理

### 6.1 响度

- 成片统一到 **−16 LUFS**，真峰值不超过 **−1.5 dBTP**。
- 推荐两遍 `loudnorm`：先测 `I / TP / LRA`，再按测量值二次归一；单遍也能用，但要回放确认没有忽大忽小。
- 口播与画面不同步超过 0.2 秒的段落，整体平移音频，不要逐句硬对口型。

### 6.2 字幕

- 硬字幕或外挂 `.srt` 均可；不要只靠简介。
- 与口播逐句一致，单行不超过 20 个汉字，最多两行；不要遮住路径标签和引用标题。
- 专有名词统一：CampusPilot、BM25、SSE、Mock、50 MB、demo / campus2026。
- 数字与单位之间留空格：`50 MB`、`51.0 MB`、`7 分 37 秒`。

### 6.3 抽掉长静默

- 逐段检查，凡超过 **2.5 秒**没有人声的片段一律抽掉；句间保留 0.3–0.5 秒。
- 不要用自动跳剪把鼠标移动切成碎镜；剪辑点放在鼠标停顿处。

### 6.4 导出

- 分辨率 **1920×1080**，像素宽高比 1:1，30 fps。
- H.264 High Profile，CBR **10 Mbps**（8–12 Mbps 区间），关键帧 2 秒。
- 音频 AAC 192 kbps、48 kHz、立体声；封装 MP4，开 `+faststart`。
- 导出后用 `ffprobe` 复核：`width=1920`、`height=1080`、时长 7:15–7:45、视频码率 8–12 Mbps、有音轨。

### 6.5 手机段合成

- 源素材是 1080×1920 竖屏，**不要拉伸、不要裁掉关键 UI**。
- 在 1920×1080 画布右侧放画中画：高度约为画面的 80%（约 864 px），宽度按比例约 486 px，加 2 px 圆角边框与阴影，模拟手机。
